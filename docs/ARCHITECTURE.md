# Architecture

Two processes that can't talk to each other directly, and how they do anyway.

```
   WoW client (Lua sandbox)                        bridge.js (Node, same machine)
   ┌──────────────────────────┐                    ┌─────────────────────────────┐
   │ WoWAI addon              │  pixels on screen  │ capture.ps1 / capture_*.py  │
   │  draws message strip ────┼───────────────────▶│  screen-captures the corner │
   │                          │                    │  decodes → {session,chat,id,│
   │                          │                    │            cwd,flags,name,  │
   │                          │                    │            text}            │
   │                          │                    │        │                    │
   │                          │                    │        ▼                    │
   │                          │                    │  claude / codex / grok / …  │
   │                          │                    │   (per chat, parallel,      │
   │                          │                    │   resumed; agents.js)       │
   │                          │                    │        │                    │
   │  LoadAddOn(WoWAI_S…)     │  files on disk     │        ▼                    │
   │  ◀───────────────────────┼────────────────────┤  writes 200 slot Inbox.lua  │
   │  PlaySoundFile(sig/…)    │                    │  flips signal/heartbeat wav │
   └──────────────────────────┘                    └─────────────────────────────┘
```

## The sandbox

WoW addons cannot open sockets, read files, run programs or receive input from other processes. What they *can* do that reaches outside:

1. Draw pixels. Anything on screen can be captured by another process.
2. Load files that already existed when the client launched, the first time each is used. Files created after launch are not discovered. A file that was already loaded keeps returning the cached content for the rest of the process, even across `/reload` (fonts, sounds, textures) — except addon **Lua code**, which is re-read on `/reload`. These rules were measured on a live Forever client by [wow-forever-codex](https://github.com/0xinuarashi/wow-forever-codex) and match what this project observes.
3. Write SavedVariables — but only on `/reload` or logout, and `ReloadUI()` can only be called from a hardware event (a key or click), never from a timer.

Everything below follows from those three facts.

## Outbound: the pixel strip

`Codec.lua` turns a message into a byte stream and packs it into 3-bit cells:

```
[0xC7 0x1A] [id hi, lo] [len hi, lo] [payload…] [Fletcher-16 s1, s2]
```

Cells are opaque `SetColorTexture` squares, with one binary level per RGB channel (8 symbols). **Robust** uses 4-pixel cells at channel endpoints; **Compact** uses the same endpoint colors at 2 pixels. **Quiet** starts with 2-pixel dark cells (channel values 16/80), then checks a 4-pixel dark variant (`quiet4`) if spatial filtering makes the smaller grid unreadable. Quiet decoding calibrates each channel from the first five fully known magic symbols and validates the entire packet checksum; the sixth symbol includes message-ID bits. Endpoint colors remain the final fallback if dark levels cannot be verified. There are 200 columns, up to 48 rows and a 3,200-byte payload limit. A full payload occupies 800×172 pixels at 4 pixels/cell or 400×86 at 2 pixels/cell.

The payload is one or more records separated by `\x1E`, fields by `\x1F`:

```
session \x1F chat \x1F id \x1F cwd \x1F flags \x1F name \x1F [context \x1F] text
```

- `session` — a random token generated when the addon's saved data is created. Numeric message IDs are pixel/signal/display counters, not request identities: SavedVariables can roll the counter back after a crash while the bridge has persisted newer receipts.
- `flags` — `n` = start a fresh agent session; `h` = hello (announce the session token, no prompt); `d` = the chat was deleted in game: drop its transcript and agent session, no prompt (the addon keeps the id in `db.forget` and resends it with each hello until the bridge acks); `c` = a game-context field sits between `name` and `text`; `allow=Rule1,Rule2` = add permission rules before running; `agent=codex` = run this chat with that agent instead of the bridge's default (absent for chats on the default). The reload outbox stores the allow list as hex text separated by `US`, so `/reload` preserves the same permission grant.
- `nonce=<token>` — immutable identity for each new question, hello or forget operation, retained across retransmissions and UI reloads. Bridge metadata advertises `requestProtocol = 1`; the addon requires it before sending a new question. Dedup receipts use `(session, nonce)`, while multipart/query ownership also includes chat identity. Legacy numeric receipts cannot discard a new nonce-bearing request. Both reload outboxes and every job-owned reply carry the nonce; the addon requires matching numeric ID and nonce before acknowledging or applying a reply. Cached numeric-only ACK sounds never acknowledge user questions. Unsupported nonce-less input is diagnosed through the bridge log and compatibility metadata, not a job error that an old client could mistake for completion.
- `model=<hex>` and `reasoning=<level>` — per-request model ID and effort overrides. Model IDs are hex-encoded so delimiters cannot become flags. The reload outbox carries the same `model` hex and plain `reasoning` fields. Absent fields use the bridge / CLI defaults.
- `context` — only present with the `c` flag: a permission-filtered short summary from `Context.lua` (at most 900 bytes), not the full snapshot. Hello and changed summaries use the existing acknowledgement mechanism; empty clears the bridge's short context.
- `profile=<id>` — the question requires a complete selected-information snapshot. `data=profile;profile=<id>;part=i/n` packets carry fragments under the same session/chat/message identity. Bridge metadata advertises `contextProtocol = 2`: `encoding=zlib64` uses native `C_EncodingUtil.CompressString` with `Enum.CompressionMethod.Zlib` and `OptimizeForSpeed`, followed by base64; `encoding=b64` is the lossless fallback when compression is unavailable or does not shrink the data. Fragments hold 3,000 characters and use negotiated pacing, normally 100 ms, with conservative backoff if full receipt stalls. Both bridge and addon must be updated; unsupported context protocol versions block new snapshot sends. Assembly and decompression precede UTF-8 decoding. Encoding/count changes, conflicting parts, invalid base64 and damaged zlib streams fail explicitly; both encoded input and decompressed output are bounded, with a 4 MiB decoded limit. Fair rotation continues until a nonce-matched queued/working/final receipt acknowledges the complete request; partial snapshots and cached sound flags cannot stop an upload. The agent never starts on partial data. Reload outboxes retain the complete hex snapshot.
- `data=query;request=<id>;part=i/n` — results of an addon information request. A `context_query` reply carries only JSON-serialized queries as Lua data, never Lua source. `Context.lua` enforces current permissions before getters run. Large results use the same multipart transport; the reload fallback uses `contextOutbox`. Presence updates prompt slot reads, with a bounded pending-context polling interval when sound notifications are unavailable.
- `text` — the message. Item, spell and quest links the player shift-clicked in (`|Hitem:2140:…|h[Fine Longsword]|h`) are expanded before sending: `[Fine Longsword]` stays in the text and the link's tooltip, read off a hidden `GameTooltip` via `SetHyperlink`, is appended in a `--- Linked from the game ---` block.

The strip stops as soon as a nonce-matched full receipt arrives, including while the request is queued before an AI worker is available. The existing retry budget and hardware-event reload fallback remain; partial-data progress is not receipt acknowledgement.

All display profiles use scale `768 / (height * dpiScale)`, from `GetPhysicalScreenSize()` and `GetScreenDPIScale()`. The addon refreshes physical sizing on sends; `UI_SCALE_CHANGED` and `DISPLAY_SIZE_CHANGED` invalidate optional display calibration and return to Robust until a new check succeeds.

`transportProtocol = 1` advertises `transport = { displays, frameIntervalMs, captureIntervalMs }`. Capture defaults to 50 ms; the bridge proposes `max(100, 2*captureIntervalMs)` for frames, so explicit slower capture settings do not silently cause systematic packet loss. Metadata is adopted through a fresh verified hello, not cached clocks. The addon keeps 500 ms conservative pacing when capabilities are unavailable.

Saving Compact or Quiet sends an exclusive, fresh-nonce `h;calibration=<display>` hello padded to the full 3,200-byte payload without character context. Capture reports the **actually decoded** profile, and the bridge echoes it in `connectionAck.display`. Requested flags, inject input and SavedVariables cannot supply visual proof. Only a fresh matching session/nonce/time and captured profile enables the candidate for user traffic. Quiet tries `quiet4` after a failed 2-pixel check before returning to Robust. The last verified geometry is remembered to avoid repeatedly trying a known-unreadable small grid, but every new session/reconnection/scale change still needs a fresh captured-frame proof. Failure preserves the preference and pending request data; it does not loop probes or weaken the checksum.


`capture.ps1` finds the game window by process name and captures a region large enough for Robust with GDI (`CopyFromScreen`, DPI-aware). All capture backends identify the actual Robust/Compact/Quiet profile, cache successful geometry, search a bounded origin window and reject collapsed calibration, clipping and bad checksums. Successful frames include `{ id, text, display }`; visual provenance comes only from this capture result. `bridge.js` restarts capture after an exit. Linux `capture_x11.py` uses libX11 (ctypes, no packages), identifies Proton windows by title when WM_CLASS is generic, and falls back from an unreadable root window to the game's drawable.

`capture_mac.py` (macOS, native client) does the same with `screencapture` on the window's top-left corner, found through System Events, and searches a taller area for the magic since the title bar pushes the UI down. Exclusive fullscreen blocks GDI capture; borderless/windowed works. HDR was not tested. On Linux, Xwayland can reject `XGetImage` on the root window with `BadMatch`, so the capture falls back to the game window's own drawable. Wayland sessions require the game to use Wine/Proton's X11 backend; native Wayland windows cannot be captured. A compositor that unredirects the game window can still hand back a black or stale frame (`capture.keepComposited` asks it not to).

## Inbound: load-on-demand slots

`install-slots.js` creates `WoWAI_S001` … `WoWAI_S200`, each a `## LoadOnDemand: 1` addon with a single `Inbox.lua`. `C_AddOns.LoadAddOn` reads that file from disk at load time; each slot can be loaded once per UI session, and `/reload` unloads them all.

The bridge doesn't know which slot the game will load next, so every publish writes the same content to all 200 (atomic rename per file, ~1 MB total, cheap). The content is the latest status of every chat:

```lua
WoWAI_SlotData = {
  ts = "...", now = <bridge epoch seconds>, cwd = "<the bridge's default folder>",
  connectionProtocol = 1,
  connectionAck = { session = "<addon session>", nonce = "<received hello nonce>", at = <actual hello receipt epoch seconds> }, -- absent before a hello
  agent = "claude", agents = { "claude", "codex", "grok", "agy", "hermes" },   -- the default agent, and the ones the bridge knows
  replies = { { chat = "...", id = 12, status = "working"|"done"|"error", text = "...", cwd = "...", session = "<agent session id>", agent = "codex", denied = { "WebSearch" }, macros = { { name = "Charge", body = "#showtooltip\n/cast Charge", icon = nil, char = false, risky = false } } }, … },
  map = { epoch = "...", version = 3, layers = { … } },  -- the agent's map layers (docs/MAP.md): for a while after they change and after every hello
  restore = { token = "...", chats = { … } },   -- only right after a saved-data reset
}
```

The addon loads a fresh slot on a schedule after each send (5, 10, 16, 24, 34, 46, 60, 80, 100, 130, 160, 200, 240, 300 s, then every 60 s) or when notification hints fire. Replies match `(chat, id, nonce)` against the pending request. `now` records when metadata was published; it is not connection authentication. Connection checks require `connectionProtocol = 1` and a fresh acknowledgement matching the current probe's addon session and nonce. Its `at` must be no older than probe start and no later than `now`; the snapshot clock must be within the 15-second check window (at most two seconds future skew). A newly received duplicate hello re-acks idempotently. The ACK is process-local and heartbeat publication never updates its receipt time or restores it from historic receipts.

A separate 100 ms ticker performs cheap readiness checks while a request, connection check or calibration is pending; idle checks remain slow. Actual slot loads still require a new notification or a bounded fallback deadline. Calibration has one scheduled read if sound hints are unavailable. A numeric reply sound can trigger at most one read per request nonce, preventing a cached playable path from exhausting all 200 slots during a long job.


The same content is written to `WoWAI/Inbox.lua`, which the game reads on `/reload` — the fallback path and the only path in `mode reload`.

## Signals: the empty-wav trick

`PlaySoundFile(path)` returns whether the file will play. An empty file won't; a valid one will; a file that has never been loaded is read fresh. So a pre-made empty `.wav` is a one-shot flag the bridge can raise at any time and the addon can poll for free:

| Files | Raised when |
|---|---|
| `sig/NNN.wav` | reply NNN is ready → load a slot now instead of waiting for the schedule |
| `ack/NNN.wav` | delivery hint for control maintenance; cached numeric flags never authenticate a hello or user request |
| `act/NNN/kk.wav` | the agent's k-th action on message NNN → live "14 actions, last 6 s ago" without spending a slot |
| `presence/kkkk.wav` | one-shot readiness after published hello/full-receipt/queued/query/final phase changes, plus periodic activity hints; never connection authentication |
| `ctl/empty.wav`, `ctl/valid.wav` | never change; at login the addon checks that empty reads as unplayable and valid as playable, and disables the whole mechanism if not |

`NNN = ((id − 1) mod 200) + 1`. A raised file stays playable for the rest of the client process even if emptied, so cached WAVs cannot prove current process availability or an end-to-end round trip. The client never wraps through already-consumed presence filenames. Sound and slot timestamps are maintenance/notification hints only. A matching newly received hello acknowledgement verifies the current connection attempt for 90 seconds from its actual receipt time, not when a snapshot was read. Repeated clocks, ACKs and job reply bodies do not renew that verification. After expiry the UI says idle/unverified, not live or dead; Send performs a new check automatically. Explicit Reconnect supersedes the old confirmation with a fresh nonce, remains visible, and times out after 15 seconds without releasing a queued message. In-flight retransmissions preserve the probe nonce. Bounded ten-minute idle metadata maintenance remains, but no 12/22-minute green grace period exists. The addon cannot instantly detect remote process exit without another observation; the badge states past verification age instead of implying a persistent socket.

## Bridge

`bridge.js` (zero dependencies), with the pure protocol code in `protocol.js` (strip records, slot files, folders, dedup; unit-tested in `tests/bridge_test.js`) and the agents in `agents.js` (one entry per CLI: the command line for a run, how the prompt is handed over, and a parser that turns its output stream into progress lines, a session id and the reply; unit-tested in `tests/agents_test.js` against each CLI's documented stream format):

- **Inputs:** capture lines; the SavedVariables outbox (fallback, written on `/reload`); `--inject` for tests.
- **Dedup:** `state.handled[session]` is a set of ids; older single-number state is migrated.
- **Folders:** the default folder is `--project`, else the folder the bridge was started from (the `wow-ai` command, see README), else `defaultCwd` in the config; it is reported to the addon as `cwd` in every slot file. A chat's folder is resolved against it (`realms` → `<default>\realms`; empty = the default). The agents keep sessions per project folder, so `state.json` remembers the folder each session ran in and a chat that changed folder starts a new session.
- **Agents:** `agent` in the config is the default; a record's `agent=` flag overrides it for that chat. Unknown names get an error reply listing the known ones; an agent whose CLI isn't installed gets one saying so (`agents.resolveCommand` looks in the installer's folder, on the `PATH`, and behind npm's `.cmd` launchers, which it unwraps to the script or native binary they run rather than going through `cmd.exe`). `state.json` remembers the agent of each session next to its folder, and a chat that changed agent starts a new session. Every slot file names the default agent and the list, so the addon can validate `/wow-ai agent` and label the bubbles; every reply record names the agent that wrote it. See [AGENTS.md](AGENTS.md) for what each CLI is run with.
- **Model catalogs:** `agents.discoverModels` resolves installed CLIs and calls their optional `modelCatalog`. Codex uses a short-lived stdio `app-server` (`initialize`, `initialized`, paginated `model/list`, then shutdown); Antigravity runs `agy models`. These run independently at startup, never start a conversation, and merge IDs into public `agentOptions` metadata. Capture and jobs do not wait; configured/custom model choices remain available on discovery errors.
- **Jobs:** one agent process per chat, up to `maxParallel` at once, queued per chat beyond that. Claude: `claude -p --output-format stream-json --verbose --permission-mode … --allowedTools … [--resume <id>]`, prompt on stdin; Codex: `codex exec --json -C <folder> --sandbox … [resume <id>] -`, prompt on stdin; Grok: `grok --output-format streaming-json --cwd <folder> --prompt-file … [-r <id>]`; Antigravity: `agy --input-format stream-json --output-format stream-json --add-dir <folder> [--conversation <id>]`, user events on stdin; Hermes: `hermes chat --query-file - --in <folder> [--resume <id>]`, prompt on stdin, plain-text reply read when the process ends. Parsers turn events into progress, sessions and final replies. A logical job's `timeoutMs` includes its addon information waits and resumed turns.
- **Permissions:** a refused tool (Claude's `permission_denials` in the result, a Grok `tool_call_update` whose status says so) is turned into an allowlist rule (`Bash(<first word>:*)` or the tool name, in Claude's syntax for every agent) and sent along as `denied`; an `allow=` flag on a later message merges them into that agent's `allowedTools` in `config.json`, including through the reload outbox. Codex has no allowlist: a `command_execution` it declined is named at the end of the reply instead.
- **Game context:** only selected short information is kept in `state.json.context`. Full `Context.lua` snapshots are assembled per session/chat/message and attached to the agent's stdin/prompt file; they are not clipped to the summary limit or copied into the chat transcript. A profile-bearing turn never re-injects the cached global summary, which may contain fields unchecked since a previous question. Every agent receives the same sharing contract. A reserved `wowcontext` JSON block pauses finalization, sends queries to the addon, and resumes the existing session with results. Internal continuations retain map side effects/permission notices and do not add another user turn. Sensitive scopes are off by default; native API namespaces are opt-in and documented getter-only. Restricted values, inaccessible userdata and closed-window data remain explicit unavailable states.
- **Transcripts:** every prompt and reply (with the agent that wrote it) is appended to `transcripts.json` per chat. The first message from an unknown session token means the addon's saved data is fresh, so the next three publishes carry a `restore` bundle (up to 16 chats, 40 messages each) addressed to that token; the addon imports chats it doesn't have.
- **Publishing:** final results immediately; progress throttled to one write per 3 s.

`supervisor.js` restarts the bridge 3 s after any exit. `npm start` / `start.ps1` run it in the current terminal; `start-window.cmd` opens its own console window (a `.cmd` running inline would make Ctrl+C trigger cmd's "Terminate batch job?" prompt).

## Addon

`WoWAI.lua` owns chats/transport/UI integration. `Context.lua` owns snapshot providers, native API discovery, serialization and permission-gated queries; `ContextUI.lua` owns the searchable virtualized checkbox panel. Both use existing `WoWAIDB` settings. The addon runs in a Lua VM for transport, sharing, query and map regression coverage.

Both inbound transports share `ApplyBridgeData` for metadata, replies, restore bundles and map layers; only slot reads refresh clock-based liveness. Selector labels and picker entries share `SelectorDefault`, while outbound requests still omit bridge/CLI defaults.

- **Chats:** `db.chats[]` with id, name, cwd, agent, model, reasoning, history, pendingId, unread, draft, and an immutable `request` snapshot with its nonce while pending. Empty choices inherit `db.settings.defaults` for the same agent, then bridge / CLI defaults; new chats inherit the current chat's choices. Saving addon defaults preserves explicit provider-specific chat overrides and resets sessions when clearing an override could otherwise leave it sticky in the CLI. Resends preserve the nonce and snapshot, including after `/reload`; pending pre-nonce requests migrate once without recollecting or trimming their original profiles or changing their saved selection tuple. A chat named `Chat N` takes its title from the first message. Deleting the last chat resets it instead. History entries are `{ role = "user"|"assistant"|"system", text, id, t, agent }`; older `claude` roles are read as assistant replies from Claude.
- **Transcript/composer:** message bodies are native multiline read-only EditBoxes, not click-to-copy FontStrings. Typing/pasting restores the immutable message; unchanged redraws do not reset selection/caret, and recycled bodies clear old focus/selection. A shared hidden FontString measures actual wrapped glyph height with the message's font, spacing and width; literal pipes are escaped only in this measurement. Per-card cached extents are recalculated when text or width changes, keeping backgrounds, action buttons and following messages below the full selectable text. Nominal point size multiplied by an EditBox line count is not a painted height. Compact header selectors, a shorter composer, and one bounded footer action row reserve most height for discussion. Latest-message navigation stays in the header, and window dragging is header-only. Each chat keeps its reading position; drafts retain whitespace across chat switches/reloads. Enter sends, Shift+Enter inserts a newline, and pending checks keep the next-message draft without sending it.
- **Windows:** shared `WoWAI.UI` palette, thin-border surfaces, buttons, labels and tooltips style only this addon's workspace, settings, sharing, menus, copy window and compact bar. The responsive workspace has a searchable/scrollable conversation sidebar, clear connection state, compact per-chat selectors in the discussion header, visible chat/recovery menus and a Settings panel with Save/Cancel/Use bridge defaults. Pickers are searchable; global Blizzard confirmation dialogs are not reskinned. Sharing has Character/Private/Advanced/Selected views, virtualized rows and a metadata-only cached catalog summary for the workspace badge. Existing Lua files and saved settings are reused; no new addon files or map/game UI changes. Slot files and `Inbox.lua` still carry public selection metadata only.
- **Scrolling:** `WoWAI.UI.ScrollFrame` combines standard ScrollFrame/Slider input with the addon's own track/thumb styling. Wheel and drag positions are clamped and synchronized when content/viewport sizes change; client-specific Blizzard scrollbar artwork is not imported into wow-ai windows.
- **Sharing permissions:** `settings.context` is the master and `settings.sharing` stores category choices. Snapshot categories are collected only when enabled; the short summary is derived from that capture rather than reading the same providers again. Native zlib/base64 encoding reduces pixel transfer cost without changing selected fields, freshness, model prompt size or permissions ([native API contract](https://raw.githubusercontent.com/Ketho/wow-ui-source-forever/forever/Interface/AddOns/Blizzard_APIDocumentationGenerated/EncodingUtilDocumentation.lua)). Additional APIs are resolved from native documentation under per-namespace/system gates; typed JSON arguments are validated before calls. UI/frame and raw addon-table access are separately sensitive; mail bodies need explicit consent for their read-status side effect. No arbitrary Lua, script getters, setters or protected actions are accepted.
- **Map tracking:** `Map.lua` keeps the active layer/index and hands its destination to ShortestPathForever's v1 routing API when available, owned as `WoWAI`. The router owns its dotted path and native bend marker; only its reported arrival advances a routed stop. Otherwise native `C_Map` / `C_SuperTrack` waypoints are used, with plain-coordinate ownership/previous tracking saved in `WoWAIMapDB.waypoint`. A timer handles native arrival, router completion/replacement and deferred combat starts. Stop/completion only releases owned tracking; no standalone compass is created.
- **Navigation workspace:** the header's Navigation entry opens a themed window owned by `Map.lua`, with searchable virtualized destination/stop rows and direct start, step, stop, map and visibility actions. `GetNavigationState()` caches a read-only snapshot by revision; changes notify `WoWAI.UpdateNavigation()` independently of world-map visibility, without rebuilding the discussion or collecting character data. Saved marks work offline. Active targets normalize when layers shrink/disappear; unordered point arrival stops at the selected destination, and deferred routing yields to another owner's route.
- **Local point edits:** `WoWAIMapDB.edits` stores per-layer additions and deletion masks over the unchanged bridge snapshot. Effective layers are rebuilt only when point data changes; `@local` is reserved outside the bridge's layer-name alphabet for My places. Deletion keys include coordinates, label, kind and duplicate occurrence, so a repeated stop can be removed individually. Additions remain when source layers disappear, and active local-point references remap their indices when the bridge regenerates a route. Delete confirmations capture their original point and reject stale replacements.
- **Game context and links:** `GameContext()` asks the client about the build, character, zone, money, talents and skill lines, each call wrapped so a missing API just leaves its line out. `ExpandLinks()` rewrites `|H…|h[Name]|h` links in a message before it is sent (see the record format above). Shift-clicked links reach the addon's input box through a `hooksecurefunc` on `ChatFrameUtil.InsertLink` (the Forever client uses the modern chat code; every shift-click, from bags, spellbook or quest log, ends there; the old `ChatEdit_InsertLink` global is hooked instead only where the new one is missing), which only inserts when that box has keyboard focus, so shift-click elsewhere keeps its normal meaning.
- **Game chat:** by default only the reply's `TL;DR:` block is printed under `[Codex · name]` (whichever agent answered): the system prompt asks every agent to end its reply with one, `protocol.splitSummary` pulls it out in the bridge, and the slot record carries it as `summary` next to the full `text` (without one the addon prints the reply's first two lines). `/wow-ai echo full` prints the whole reply line by line instead. Both come with `[reply]`/`[open]` hyperlinks (`|Hwowai:…|h`, handled via `hooksecurefunc("SetItemRef")`). `/ai`, `/ask`, `/wowai` and the old `/wow-claude` are aliases of `/wow-ai`; free text is sent as a message, and a line whose first word is a subcommand only runs it when the rest fits that subcommand (nothing after `delete`, one word after `agent`, `on`/`off` after `context`), so `/ai delete the unused imports` is a message. `/r` is handled by wrapping `ProcessChatType`, `SendMessage` and `SendText` on each chat edit box: when an agent was the last messenger, the box shows a repainted "To Codex [name]:" header and Enter routes to the addon with the box cleared first, so the game never sends anything; the underlying chat type is untouched, and `UpdateHeader`/`ClearChat` hooks end agent mode on Tab, `/s`, Esc or a real incoming whisper.
- **Reload fallback:** `ReloadUI()` needs a hardware event, so "auto" reload is a hidden keyboard-capturing frame with `SetPropagateKeyboardInput(true)` that reloads on the player's next keypress once the interval has elapsed. Only armed when pixels or slots can't work.

## Limits and known issues

- The client's saved-data wipe (observed on the beta) is outside the addon's control; recovery depends on the bridge having been running.
- 200 slots per UI session. Each reply costs one slot when the readiness signal works, about four otherwise; `/wow-ai reload` resets the pool.
- A raised signal file stays "valid" in the client until a full restart, so slot numbers that wrap around (every 200 messages) lose the cheap signals until then. Self-detected.
- Message capacity ≈ 3.2 KB per send; longer text is refused with a hint.
- Replies are published in full (a ~3 KB message can produce a 60 KB reply; that is fine for a slot file). The bridge-side transcript keeps the first 4000 characters of each message, and a restore sends back the last 40 messages per chat at 2000 characters each.
- Windows, Linux with the game under Wine on X11 (see [INSTALL-LINUX.md](INSTALL-LINUX.md)), or macOS with a native client (README, "macOS (native client)"; contributed and tested live by its author).
